# Agent instructions for OBS Clock

## Product and scope

- Public name: OBS Clock. Current version: 1.1.0.
- Windows filename and folder: OBS-Clock.dll in an OBS-Clock folder.
- Preserve the internal source ID `simpleclock_source`. It is a compatibility key,
  not a branding string. Preserve saved setting keys and intentional migrations.
- Windows x64 / OBS 33 is the current working target. Mac Intel, Mac Apple Silicon,
  and Linux builds are now in scope with native GitHub Actions builds.
- Keep changes incremental, reviewable, and testable. Do not expand scope because
  a possible future feature is mentioned in documentation or a concept graphic.

## Behavior contracts

- All option checkboxes follow the Opacity slider. Keep related message controls
  together. The optional background image checkbox and picker stay at the bottom.
- Show message is the master switch. Only when on should End time, Message,
  the external text-source option, and the timing note be visible.
- Only checking the external text-source option reveals its dropdown.
- Message visibility is the final hour before End time in the selected zone,
  repeating daily. Use MM:SS, from 60:00 down to 00:01; clear at End time.
- Unchecked Override artwork colors hides color controls and restores default
  artwork/text colors without deleting the saved choices.
- Disabling Use background image hides its picker and retains its image path.
- An external text source receives the complete Message plus MM:SS. Update only
  its `text` setting; preserve its font, transforms, colors, filters, and visibility.
- Use UUIDs for external source bindings. Clear only the output owned by this
  clock when switching targets or disabling/removing the publisher.
- The local clock must not reserve an inline countdown row in external mode.

## Engineering safeguards

- OBS 33 uses `gs_image_file_ex`; do not restore the removed older image API.
- Never pass FILE pointers between OBS's C runtime and the plugin's C runtime.
  Open/write/close embedded-asset files within one runtime.
- Maintain graphics-context ownership for texture/image lifecycle operations.
- Do not hold the clock mutex while looking up or updating other OBS sources.
- Keep artwork and shaders embedded. Runtime extraction is implemented; installation
  should continue to require only one Windows DLL.
- `src/embedded_assets.hpp` is generated by `scripts/embed_assets.py`. Regenerate it
  after changing files under `data/`; do not edit byte arrays by hand.
- Do not regenerate all artwork for a small code change. Some artwork scripts rely
  on Linux font paths; the generated assets are already supplied.

## Validation and delivery

- Read `docs/BUILDING.md` and `docs/TESTING.md` before building.
- Run appropriate checks; do not call static import/compile checks a live OBS test.
- Preserve user settings during upgrades and test the relevant migration paths.
- Update VERSION, CMake, C++ version labels, Windows resources, CHANGELOG, README,
  and guide version metadata when a version is intentionally changed.
- Update USER.md first for user-facing instructions, then regenerate the Word guide
  with `tools/build_user_guide.py`. Render and inspect every page after layout edits.
- Keep generated PDF/PNG QA files outside the deliverable unless explicitly requested.
- Document build/test limitations honestly. Verify hashes when packaging binaries.
- Do not publish a Git remote, release, or external message unless the user asks.
